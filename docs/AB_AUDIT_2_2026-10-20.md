## Findings and fixes

| Finding | Reproduction | Correction |
| --- | --- | --- |
| Non-text optional metadata could become invented text or unsupported storage values | Synthetic object-valued DOI/type/ID/URL/abstract/venue fields could be accepted. In particular, a raw type object could reach SQLite outside the provider error handler when categories were cleared. | Provider text fields accept strings or missing values. Venue lists contain strings; malformed structures use the existing invalid-response/page-rejection path. An isolated UI test verifies that the other provider still saves results and no malformed value reaches storage. |
| Missing author-name parts rejected usable Crossref pages | `given: null` or `family: null` caused string joining to fail. | Treat missing name parts as empty while retaining the supplied name parts. Structured non-text name values still fail validation. |
| Abstract reconstruction silently overwrote conflicting positions | Two different words at one position silently replaced the first; invalid negative/boolean/string positions could produce misleading order/text. | Reject invalid or duplicate positions through the existing page error policy. Valid repeated words at distinct positions still reconstruct in order. |
| Bare OpenAlex DOI produced an unusable relative record link | A bare DOI value was returned directly as `url`. | Build a resolver URL from the normalized DOI; keep the native OpenAlex record ID as available source evidence. |
| Invalid programmatic bounds/categories could reach a provider or fail inconsistently | Invalid year types/ranges and unsupported selections were not rejected consistently before requests. | Canonical shared settings validate CE input bounds and supported categories before network I/O. This does not impose the input widget's range on unbounded source metadata. |
| Run exports and history could misstate actual search context | `make_run` and `history_note` could label an existing retrieval with a different query, year range, selection or budget. An earlier test itself labelled unbounded results as bounded. | Capture the actual trimmed query and canonical settings at retrieval start. Refuse inconsistent run/history labels; fix the misleading fixture to retrieve with the settings it asserts. Snapshot selections so later caller mutation cannot change the captured context. |
| Duplicate source attempts or impossible insertion counts could produce misleading manifests | A provider could appear twice in one run and be ambiguously attached to history; insertion counts could exceed run-unique records. | Require one aggregated retrieval result per provider and an integer insertion count between zero and the unique count, or null when unknown. Refuse missing measured context and history attachment to an unknown/mismatched provider attempt. |

The metadata/context regressions were run before fixes and failed, establishing that they exposed behavior beyond the passing 80-test baseline. Additional guards cover related edge cases. No model, new source, schema change or product workflow was introduced.

## Handover and limits

Use `retrieve` to obtain measured results, then `make_run` with the same query/settings. Legacy tuple searches do not carry measured run context and cannot substitute for this boundary by constructing contextless results. A zero-request cooldown attempt may carry planned settings, but is explicitly recorded with no accepted pages/records. History retains version two and ZIP manifests retain format version one; their shapes are unchanged. Previously saved history/run artifacts are not retroactively verified or rewritten.

The query/settings snapshot and history checks guard ordinary misassociation; they are not cryptographic signatures or immutable evidence archives. Treat source results and captured run data as read-only. Strict shape validation protects representation/storage, not the truth of provider metadata, DOI existence, semantic relevance or scientific conclusions. Invalid pages remain rejected as a unit and do not contribute accepted-page counts.

The existing sampled live report was not rerun after these normalization changes. Broad recall, independent totals, actual outages/rate limits, concurrency, browser rendering/download transfer, crash/disk-full recovery and other runtimes remain unverified. No per-field/passage attribution, full-text analysis, resumable traversal or crash-atomic paper/history storage was added.
