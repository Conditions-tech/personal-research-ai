## Evidence and output contract

`review/analysis.py` uses only the captured abstract and citation metadata for one paper. The six approved fields are objective, method, dataset, results, limitations and conclusion. Reviewer notes, review protocol and other papers are not sent. Metadata/abstract text is explicitly untrusted data in a versioned system prompt. No retrieval/full-text/tool invocation is available to the model.

Version-one responses use a strict identity-bound JSON object with six kind/text/excerpt fields and lexical/numeric checks. That legacy contract remains unchanged for saved drafts. Versions two through four return identity-bound sentence-ID selections; version five returns complete source text or an empty string. In each case, the application derives normalized `paper-statement`/`missing` fields directly from eligible source spans. Free model paraphrases, new numbers and interpretation generation are unavailable in v2–v5; human-authored interpretation remains. Missing means no qualifying quote selected, not proven absence. Exact source spans retain negation but still require field/scientific review. See the [versioning/API details](QUOTE_FIRST_C2_2026-10-20.md).

**Exact matching establishes text presence only.** An irrelevant excerpt, invented claim using the same numbers, altered negation or incorrect interpretation can pass lexical checks. An explicit regression demonstrates a scientifically unsupported claim passing those checks. Human review of every field remains mandatory. Mock injection tests verify data/contract boundaries, not real-model instruction resistance or scientific reliability. Shared titles are never treated as identity; identical excerpts across papers cannot by themselves establish authorship.

Each proposal retains a unique draft ID, timestamps, copied citation/record/source observations, captured run fingerprint, original abstract, model name/digest, runtime version, full exact system/user prompt, response schema, generation settings, prompt version, raw response and response fingerprint. The original discovery run remains separate and unchanged. Existing provider conflicts/merged-field attribution limits remain. Hashes are accidental-change checks, not signed provenance or scientific truth.

## Existing workspace integration and persistence

- Existing screening and reviewer-authored `analysis` notes remain intact. Generated `ai_drafts` are separate. Generation returns a copied workspace only after validation; missing/long abstracts, malformed responses and backend failures preserve prior notes, decisions and proposals.
- The local backend is checked only on explicit button clicks; ordinary rerenders/imports never probe or generate. Generation rechecks inventory, selected GGUF/size/quantization and runtime identity before sending paper evidence, and checks the model digest again afterward. No pull/install/start/remote URL/cloud option is provided.
- Proposals start pending. Acceptance requires the UI checkbox attesting every claim/excerpt was checked and a reviewer note. Rejection also requires a note. A decision is retained with a timestamp; reviewed proposals are immutable decisions in this slice. These are user assertions, not proof that review happened.
- Comparison CSV retains existing manual columns, adds `ai_` columns for the **latest explicitly accepted** proposal, and identifies that proposal/model/prompt/reviewer decision. Pending/rejected claims never become comparison findings. An older accepted proposal remains visible if a newer one is pending or rejected; `ai_latest_status` discloses the latest attempt. All proposals are visible in the workspace/JSON.
- Reviews without AI stay format version 1. First generation promotes to version 2. Current reopening validates both; AI claims/context/prompts/settings/decisions are validated again on reopen and export. Review format 2 protects against the old C1 reader silently discarding AI fields: it rejects that version. Keep exported JSON with the current application. Proposal formats 1–5 are paired with their explicit protocol inside root review format 2; the v6 diagnostic is not an app proposal format and is rejected by normal review import. Older readers reject unknown proposal versions. Unknown prompt versions/models require a future explicit compatibility implementation, not silent migration.
- Up to 20 retained proposals per paper; no silent eviction. A new proposal that would exceed the existing 10 MiB JSON reopening limit is refused without replacing work. C1's manual text remains user-controlled; oversized manually authored work can still exceed that importer limit. The UI now warns when a download cannot reopen, while preserving the complete JSON and notes. Download early. Large-file reopening, large-workspace performance, revision editing and durable/multiple-review storage remain future work.
- Review data remains session-only and downloaded explicitly. No SQLite review tables/schema, production writes, historical-script edits, dependency changes or Git operations were introduced. Full text, synthesis, research gaps and paper-writing remain outside C2.
